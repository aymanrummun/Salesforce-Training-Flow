Section 1 Validation Rules

🛠️ Validation Rules

📛

Best Practice Reminder: Rules check if an expression evaluates to TRUE (which indicates an error condition). Keep rule names concise, avoid the word "Validate" in names, and always provide helpful error messages.

Practice 1: Phone or Email Required

Use Case: Ensure leads have at least one valid method of contact (Phone or Email).

Target Object: Lead

Task: Create a Validation Rule that triggers if both Phone and Email are blank.

Error Message: Please enter at least a phone number or an email address.

Practice 2: Parent Record Check

Use Case: Validate parent Account details when a Contact with a Job Title is created or updated.

Target Object: Contact

Task: Prevent saving a Contact if the Contact's Title is populated BUT the parent Account.Industry is blank.

Error Location: Field -> Account Name

Error Message: Please specify the Account's Industry before adding this Contact.

Practice 3: Secure Website Enforcer

Use Case: Standardize company web addresses across Accounts.

Target Object: Account

Task: Trigger an error if Website is populated but does not begin with https://.

Error Location: Field -> Website

Error Message: Website must start with https://

Practice 4: Enterprise Account Revenue

Use Case: Enforce financial tracking on active prospects.

Target Object: Account

Task: Require AnnualRevenue whenever Type is set to Prospect.

Error Location: Field -> Annual Revenue

Error Message: Please enter Annual Revenue for Prospect accounts.

Section 2 Screen Flows

🖥️ Screen Flows (User Interactive)

Practice 1: Quick Contact Creator

Scenario: Enable sales reps to quickly log new contacts while in the field.

Steps & Elements:

  • Screen Element (Collect Contact Details):
    1. Text Input (First Name)
    2. Text Input (Last Name - Required)
    3. Email Input
    4. Lookup Input (Account Name)
    5. Add Help Text for Family Name
    6. Add Validation (Length of LastName should be greater than 3 character).
  • Create Records Element: Object: Contact. Map screen inputs directly to fields.

Practice 2: Bulk Opportunity Stage Manager

Scenario: Allow sales managers to update stages across multiple active opportunities.

Steps & Elements:

  1. Get the Opportunity Records
  2. Display the opportunities for the end user to choose.
  3. Once the user has chosen, provide the stage they want to chnage to
  4. Update the records from the value provided.

Section 3 Record-Triggered Flows

⚡ Record-Triggered Flows

Practice 1: Auto-Assign Account

Scenario: Automatically assign Healthcare opportunities to a central account.

  • Object: Opportunity | Trigger: Record is created | Condition: Industry__c Equals HealthCare
  • Get Records: Find Account where Name = Health Trust.
  • Update Records: Set $Record.AccountId = Get_Health_Trust_Account.Id.

Practice 2: Last Modified Tracking

Scenario: Audit when a flow updates an opportunity record.

  • Object: Opportunity | Trigger: Record is updated | Optimize: Fast Field Updates (Before-Save)
  • Assignment Element: Set $Record.Last_Modified_By_Flow_Date__c = $Flow.CurrentDate

Practice 3: Parent Account Last Case Closure

Scenario: Keep parent Accounts informed when a related Case is closed.

  • Object: Case | Trigger: Record is updated | Condition: Status Equals Closed
  • Decision: Is {!$Record.AccountId} IS NULL = FALSE?
  • Update Records: Filter: Account where Id = {!$Record.AccountId}. Field Update: Last_Case_Closed_Date__c = {!$Record.ClosedDate}

Practice 4: Scheduled Path (Escalation)

Scenario: Schedule a background check 3 days after a Case is escalated.

  • Run Immediately Path: Update Element to Set $Record.Reviewed__c = FALSE
  • Scheduled Path: Offset: 3 Days After | Time Source: ClosedDate. Update Element to Set $Record.Ready_For_Review__c = TRUE

Practice 5: Asynchronous Path

Scenario: Recalculate related line-item totals in the background when an Opportunity stage changes.

  • Path: Run Asynchronously.
  • Logic: Get related OpportunityLineItems -> Loop through them and sum Quantity -> Update parent Opportunity TotalQuantity__c.

🚀 Autolaunched Flows (Subflows)

Practice 1: Update Account Rating

Input Variable: varAccountId (Text, Available for input)

Logic: Get related Opportunity records -> Count them -> Decision node (Hot if >5, Warm if 2-5, Cold if <2) -> Update Account.Rating.

Practice 2: Apply Discount

Input Variables: varTotalAmount, varDiscountPercent

Output Variable: varDiscountedAmount

Formula: {!varTotalAmount} - ({!varTotalAmount} * ({!varDiscountPercent} / 100))

Practice 3: Auto-Create Task

Input Variables: varRecordId, varDueInDays

Output Variable: varTaskId

Logic: Create Task (Subject="Follow Up", WhatId=varRecordId, ActivityDate=Today+varDueInDays).

Section 6 Comprehensive

🚩 Case Study: Incident Scoring & Escalation Engine

📊

Requirements Summary: Case object (Type = Incident). Required Fields: Case Reason, Description, Status, Priority (Low, Medium, High), Region (US, EU, APAC). Action: If calculated Score > 85, automatically send an email alert to the system admin.

Scoring Rules:

  • If Region = "US" AND Priority = "High" → Score = 90
  • If Region = "EU" AND Priority = "High" → Score = 80
  • Default / Other Combinations → Score = 50

Solution Option A: Formula Field (Recommended)

Create a Formula Field Score__c (Number, 0 Decimals):

Formula
IF(
  AND(ISPICKVAL(Region__c, "US"), ISPICKVAL(Priority, "High")), 
  90,
  IF(
    AND(ISPICKVAL(Region__c, "EU"), ISPICKVAL(Priority, "High")), 
    80, 
    50
  )
)

Then create a Record-Triggered Flow: Entry Criteria: Score__c > 85 → Send Email Action.

Solution Option B: Flow-Based Logic

Create a Before-Save Record-Triggered Flow on Case:

Flow Logic
       [ Start: Case Created/Updated ]
                     │
    ┌─────────────────────────────────┐
    │   Decision: Check Score Logic   │
    └─────────────────────────────────┘
       │             │            │
  (US+High)      (EU+High)   (All Others)
       │             │            │
 [Set Score=90] [Set Score=80] [Set Score=50]
       │             │            │
       └─────────────┼────────────┘
                     │
    ┌────────────────────────────────────┐
    │ Decision: Is Score Greater Than 85?│
    └────────────────────────────────────┘
             │                 │
           (Yes)              (No)
             │                 │
     [Send Email Alert]      [End]
